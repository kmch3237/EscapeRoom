## 오늘 배운 핵심 개념 (면접용)

### A. 이력 보존 설계 (이 프로젝트 관통 철학)
- 승인 → PARTY_MEMBER INSERT (신청서 안 지우고 APPLY_ID로 연결 = 이력 추적).
- 거절 → PARTY_APPLY DELETE (멤버였던 적 없어서 이력 불필요 → 하드 삭제).
- 강퇴 → PARTY_KICK INSERT (멤버는 그대로, "강퇴 딱지"만 붙임 = soft delete). 조회 시 NOT EXISTS로 제외.
- 예약취소(RESERVATION_CANCEL) / 슬롯삭제(RES_DROP)도 동일 = soft delete.
- 한 줄: "중요한 사건은 지우지 않고 이력 테이블에 남긴다."
- 면접: "삭제를 어떻게 처리했나?" → "의미 있는 이력(취소/강퇴)은 실제 삭제 대신 이력 테이블에 기록하고 조회 시 제외하는 soft delete로 처리."

### B. 인가(Authorization) 3종
- 역할 기반 — "파티장인가" (승인/강퇴). party.userId 와 내 userId 비교, 또는 멤버 중 HOST 찾기.
- 소유권 기반 — "내가 쓴 건가" (댓글 삭제). comment.userId != user.userId → 403.
- 소속 기반 — "멤버인가" (게시판 보기/댓글 등록). 멤버 목록에 내가 있나 stream().filter.
- 같은 인가여도 동작마다 확인 기준이 다름. URL 직접 접근 못 막으니 서버가 매번 확인.

### C. 값이 서버로 들어오는 통로
- @PathVariable — URL 경로에 박힌 값 (/party/update/5 의 5). 대상을 가리킴.
- @RequestParam — 폼/쿼리로 넘어온 값 (사용자가 채운 값).
- GET(폼 열기)은 PathVariable, POST(저장)는 RequestParam 위주.

### D. put vs set (그릇이 다름)
- set → DTO 객체에 값 넣기 (party.setPartyName).
- put → Map 보따리에 key-value 넣기 (map.put("slotId", ...)).
- 매퍼에 값 넘길 때 Map(put)이든 DTO(set)든 둘 다 가능. 값 적으면 Map, 필드 많으면 DTO.

### E. 예외를 HTTP 상태코드로 던지기
- throw new ResponseStatusException(HttpStatus.FORBIDDEN, "메시지").
- 401 인증안됨 / 403 권한없음 / 404 없음.
- 프로시저의 RAISE_APPLICATION_ERROR 와 같은 발상의 자바 버전. AJAX가 상태코드 받아 처리.

### F. 두 테이블 분리 UPDATE (파티 수정)
- 파티 정보(이름/코멘트) → UPDATE PARTY.
- 슬롯 연결(어느 시간대) → UPDATE PARTY_ROOM (RES_OPEN_ID). 슬롯 바뀔 때만 실행(효율).
- UPDATE/DELETE 에 WHERE 필수 — 없으면 전체 변경 대참사.

### G. 프론트 문법 (JSP+JS+jQuery 혼합)
- |...| = 리터럴 치환 (글자+값을 + 없이). th:text="|${age}세|".
- th:inline="javascript" = script 안에서 서버값 쓰게 열어줌. /*[[${x}]]*/ 기본값 (서버 돌면 진짜값, 안 돌면 기본값).
- CDATA = JS 특수문자(<>&) 보호. (MyBatis XML 에서 쓰던 그것과 같은 목적)
- 이벤트 위임 $(document).on("click",".cls",fn) = 동적 요소는 거는 순간 없어서 안 걸림 → 항상 있는 부모가 클릭 순간 검사.
