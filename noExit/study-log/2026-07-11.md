## 오늘 배운 핵심 개념 (면접용)

### A. fragment vs JSP include
- JSP `<%@ include %>`도 공통 UI 재사용은 됨. 차이는 fragment가 **파라미터를 받을 수 있다**는 것.
- `th:fragment="ownerSide"` + `th:replace="~{fragments/sidebar :: ownerSide}"`.
- 헤더에 화면별 제목 넘기기처럼 **함수처럼 재사용** 가능 → include를 fragment로 바꾼 진짜 이점.
- 면접: "공통 UI 어떻게 재사용?" → "fragment로 분리, th:replace로 참조. include와 달리 파라미터 전달이 돼서 재사용성이 높음."

### B. 목록 반복 렌더링 (내 약점이었음)
- 헤더 줄(th:each 없음)은 화면에 1번, `th:each` 줄은 명단 수만큼 복제(붕어빵틀). 코드엔 1줄, 화면엔 N줄.
- `th:each="m, st : ${list}"` → 두번째 변수 `st.count`로 순번(varStatus 대체).
- 가로/세로: `class="row"` 있으면 안쪽 col이 가로 배치, 없으면 div라 세로로 쌓임.
- 반복문 안에 폼: 각 항목이 자기 데이터(userId) 담은 독립 폼을 가져야 함. 밖에 하나만 두면 누구 건지 특정 불가.

### C. 자주 쓴 Thymeleaf 문법 (JSTL/스크립틀릿 대응)
- `th:selected="${조건}"` — option 기존 선택값 유지 (`<c:if>selected` 대체).
- `th:utext="${paging}"` — HTML 그대로 출력 (th:text는 이스케이프됨). 자바가 조립한 페이징 HTML 뿌릴 때.
- `dto?.themeName` — null 안전접근. 등록/수정 겸용 폼에서 신규(dto null)일 때 필수.
- `#dates.format(날짜,'yyyy-MM-dd')` — fmt:formatDate 대체.
- `#numbers.formatInteger(price,1,'COMMA')` — 천단위 콤마 (fmt:formatNumber).
- `#numbers.sequence(0,23)` — 시/분 option 자동 생성.
- `#temporals.createToday().plusDays(1)` — JSP 스크립틀릿(`<%= LocalDate.now() %>`) 대체. Thymeleaf는 스크립틀릿 불가.
- `th:onclick="|fn(${a},'${b}')|"` — onclick 안에 서버값 전달.
- 중첩 `<c:choose>` → 배타적 `th:block th:if` 여러 개로 분해.

### D. selectKey (어제 이어 복습)
- Oracle은 auto increment 없음 → 시퀀스에서 번호 먼저 뽑아야 함.
- `<selectKey keyProperty="attendanceId" order="BEFORE">SEQ.NEXTVAL</selectKey>` → 뽑은 번호를 DTO에 도로 심고 그 번호로 INSERT.
- order=BEFORE(Oracle) vs AFTER(MySQL: INSERT 후 번호 생김).

## 오늘 관찰된 내 약점 (고치는 법)
- **반복 렌더링 감각 약함(개선됨)**: "헤더 1번 + th:each는 복제"가 안 잡혔음 → 붕어빵틀 비유로 잡음. 목록 볼 때 "이 줄이 몇 번 찍히나"를 먼저 생각.
- **가로/세로 헷갈림**: HTML 배치가 왜 옆/아래인지 몰랐음 → `class="row"`(가로) 유무로 판단하는 습관.
- **데이터 흐름 추적(진행중)**: "이 데이터 어디서 와서 어디 쓰이나"를 계속 실제 값으로 따라가는 연습 필요.
- **출력 과부하**: 표/코드 많이 주면 오히려 이해 안 됨. (Claude 쪽에서 간결하게 조정)
